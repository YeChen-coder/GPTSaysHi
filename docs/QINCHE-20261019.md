## Display and streaming

QinChe transmits **only a cropped lossless mouth PNG with transparent pixels outside the actual mouth support**. Its RGB is already feathered; the PNG support must not multiply the soft alpha a second time. The viewer keeps the same native video visible while speaking and aligns the video to the mouth timeline. It corrects drift beyond two frames rather than seeking on every frame.

The previous implementation covered the native video with full-frame JPEGs. That changed the color/decode path for clothes, skin and background as well as the mouth; the old idle video also lacked explicit color signaling. The new idle is encoded directly from the native RGB cache with a BT.709 matrix, limited range and explicit primaries/transfer tags. Full-frame JPEG is still used by the independent Gentleman profile.

Viewers use `/view?protocol=2`; refresh after upgrading. This prevents a stale full-frame viewer from stretching a mouth PNG across the entire screen. The audio publisher protocol is unchanged: timestamp header plus 24 kHz mono PCM16. App, Classic and browser source takeover retain the same behavior.

Persistent model residency, silence-based shape warmup, GPU reference caching, thread limits, continuous resampling, four-second past history, a two-frame worker queue, four-frame browser queue, stale decode cancellation and incremental EOF delivery remain active. The fast mode has no extra future-feature waiting, with 100 ms audio packets and about 1.33 ms FIR lookahead. End-of-audio detection now requires a receive timeout so computation time alone cannot split queued continuous speech.
